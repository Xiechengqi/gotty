# 共享终端尺寸与刷新恢复

一个 GoTTY 进程仍然对应一个 PTY。所有直连、Hub 和分享客户端看到同一程序状态；无法让同一个 Vim 同时拥有两套独立行列数。

默认 `resize-policy=adaptive`。只有可见、可写、仍有效的客户端参与选举：有精细指针及悬停能力的桌面端优先，其次为无法识别输入能力的客户端，再次为触屏客户端。同类候选采用实际可用行列数乘积排序，只有容量至少增加 20% 才替换健康控制端；容量相同时优先较早连接。候选和其尺寸需要稳定 500ms。始终采用一个真实客户端的完整网格，不分别拼接最大列数和最大行数。

手机先连接时适配手机；电脑随后打开时自动采用电脑网格。手机的连接、刷新、旋转或软键盘变化不会缩小仍可见的桌面控制端。设备识别结合指针能力和视口短边，避免仅凭横屏宽度把手机识别为桌面。连接数提示显示共享网格、本地容量、控制端类别和选择原因；客户端仍按服务端确认尺寸绘制，小窗口通过内部滚动查看。

手机和其他小窗口会在本地纵向滚动到实时光标行。普通输出、刷新恢复、旋转和键盘高度变化都会重新检查可见位置；`clear` 和 Vim 按实际光标位置做最小滚动，不强制显示屏幕底部的空白行。查看历史或选择文字会暂停跟随，新输出保留所读内容的位置；回到实时位置、点击“回到输入位置”或输入/粘贴时恢复。横向滚动独立保留，仅本端主动输入或返回时按需露出光标。

手机软键盘上方的快捷键占用实际布局高度，并避开安全区域。可视区域的高度与顶部平移一起处理，原生双指缩放不重新布局或调整 PTY。Hub 与直连 GoTTY 复用 `terminal-core` 的同一套视口逻辑。软刷新保留历史浏览位置，整页刷新重新跟随恢复后的实时位置；这不提供进程重启后的历史存储。

控制端隐藏 2 秒后可让权，随后仍需候选稳定期。支持新协议的前台页面每 3 秒续约，15 秒没有续约则失去资格，即使 WebSocket 仍存在。页面失焦、打开设置不等于隐藏。旧客户端没有续约协议，继续按连接和显式可见性报告处理。没有合格候选时保留最后网格。

显式配置 `leader`、`fixed`、`median` 保留原语义。`leader-select`、`leader-switch` 和手动接管只作用于 `leader`，不会改变自适应策略。直连页面的接管按钮在其他策略下禁用；Hub 无手动接管入口。已在配置文件写入 `resize_policy = "leader"` 的部署需要主动改为 `adaptive` 才启用新策略。完整效果需要同时升级 GoTTY 与 Hub；旧 Hub 可以显示统一网格，但不能提供新客户端的完整续约与输入能力信息。

控制客户端断开后，默认保留尺寸所有权 5 秒。同一浏览器标签页刷新后使用 `sessionStorage` 中的随机身份恢复所有权；不存终端文本、密码或令牌。Hub 再把身份绑定到实际登录账号。其他连接仅在宽限期到期后参与后备选举。`leader` 策略的 `latest` 只决定后备顺序；`leader-switch=never` 保持最后网格，直到同身份恢复或有人显式接管；`on_idle` 根据终端输入活动判断空闲。resize 使用尾部防抖，最后一次尺寸请求不会被丢弃，PTY ioctl 成功后才确认新尺寸。

只读诊断 `GET /-/terminal-state`（支持配置的路径前缀）返回当前行列数、策略、控制端临时 ID/设备类别/可见性、选择原因和最近尺寸来源。使用现有本机管理认证，公共分享入口禁止访问；不要求开启命令 API。不返回浏览器身份密钥、账号凭据或终端内容，也不创建终端连接、调整 PTY 或追加回放事件。

配置项：

| CLI / HCL | 默认值 | 含义 |
| --- | --- | --- |
| `--resize-policy` / `resize_policy` | adaptive | 自动桌面优先；显式指定 leader/fixed/median 保留原行为 |
| `--leader-grace-ms` / `leader_grace_ms` | 5000 | 断线后后备选举的宽限期，范围 0–60000 ms |
| `--history-lines` / `history_lines` | 5000 | 普通屏幕保留的历史物理行，范围 0–50000，0 表示关闭历史 |
| `--history-replay-bytes` / `history_replay_bytes` | 524288 | 旧协议客户端的原始字节回放上限 |

新的浏览器通过初始化消息 `ReplayVersion=2` 使用状态恢复。服务端影子 VT 模型同步处理 PTY 输出和已确认的 resize；普通屏幕、滚动历史、备用屏幕、光标、样式、终端模式及未完成的 UTF-8/ANSI 序列一起生成快照。断线重连使用同一 epoch 中的连续事件序号，输出和尺寸事件共享顺序。客户端仅在 xterm 解析完成后确认序号；发现缺口、事件超出保留范围或终端重启换 epoch 时，重新请求快照。

Hub 的“刷新”保留现有 xterm 和滚动历史，仅重连传输；有文件传输时保留原来的中断确认。整页刷新从 GoTTY 的内存状态恢复。输入及终端查询回送在历史解析完成后才放开，历史内容不进入 ZMODEM 探测器，也不重新执行历史剪贴板指令、查询或文件传输。普通缓冲区重排保留软换行，与两端 xterm 默认的 `reflowCursorLine=false` 对齐。

实时终端查询只接收一个浏览器的自动响应，避免多个客户端同时回送设备属性、光标位置或颜色而干扰 Vim。优先选择可见的尺寸控制客户端；它断线或隐藏时暂选最早的可见可写连接，不改变尺寸租约。自动响应不算用户输入活动；光标位置响应需与近期真实查询关联，保留普通方向键、修饰功能键和粘贴输入。

边界：

- 历史同时受行数、128 MiB 的保守单元格存储预算和快照历史序列约 4 MiB 的预算约束，先到达的上限生效；当前屏幕与解析状态另计。事件日志约 10 MiB，旧协议原始字节缓冲另有 10 MiB。
- 超出保留范围会淘汰较早输出，整页恢复后显示提示。保留的是终端展示状态；不是磁盘归档，也不能恢复程序内部已经清除的历史。
- 状态只在 GoTTY 进程内存中。进程退出、重启、重启 PTY、`clear` 清理滚动历史后，旧历史不能恢复。备用屏幕本身没有滚动历史。
- 文本、常用 ANSI/VT 模式和 Vim 是恢复目标；图片、Sixel、终端扩展私有状态及历史超链接元数据不作为可恢复内容。Unicode 表版本与 xterm Unicode11 不同的新增字符仍可能有宽度差异。
- 两个项目需一起升级以获得完整效果。旧客户端/旧网关继续走原有 `tail/resume`；不支持尺寸接管的旧 GoTTY 不会被新界面当作支持该能力。

VT 的 MIT 源码与 GoTTY 补丁说明位于 `third_party/vt`。升级该目录必须同时验证 Go 测试和真实 xterm 的快照、重排与 Vim 回归。终端核心源码位于 `js/packages/terminal-core`；Hub 使用同版本 vendor 包，需运行其 `scripts/check-core.py` 检查源包一致性。
